
# NIST CSF 2.0 — Gap Assessment Methodology

**Company:** Cedar Ridge Services
**Assessment Type:** Simulated Internal Gap Assessment
**Scope:** 20 selected NIST CSF 2.0 outcomes

## 1. Assessment Objective

Evaluate Cedar Ridge Services' existing cybersecurity practices against selected NIST CSF 2.0 outcomes.

The assessment will identify gaps between current and desired security practices and recommend improvements appropriate for a 50-employee IT services company.

## 2. Assessment Process

1. Review the company security profile and assessment scope.
2. Request relevant security policies and supporting evidence.
3. Review each policy against the selected CSF outcome.
4. Evaluate available evidence of actual implementation.
5. Document the Current Profile and desired Target Profile.
6. Identify security gaps and their business implications.
7. Prioritize recommendations based on risk and available resources.

## 3. Assessment Criteria

Each outcome will receive a Current Implementation Status.

| Status | Definition |
|---|---|
| Implemented | Available evidence supports that the selected outcome is achieved within the assessment scope |
| Partially Implemented | Some relevant practices exist, but important elements are missing |
| Not Implemented | Evidence supports that the necessary practice is absent |
| Not Assessed | Available information is insufficient to determine implementation |

Evidence sufficiency will be evaluated separately:

- Sufficient: Evidence supports the assessment conclusion.
- Limited: Evidence exists but does not fully support a conclusion.
- Not Provided: Requested evidence is unavailable.

A missing document does not automatically mean that a control is absent.

## 4. Current and Target Profiles

Current Profile: Document the cybersecurity outcomes the company currently achieves, supported by available evidence.

Target Profile: Describe the desired practices appropriate for the company's business risks and resources.

Gap: Identify the difference between the current and target practices.

Targets will be established based on business needs rather than assuming every outcome requires the same level of implementation.

## 5. Evidence Review

Evidence may include:

- Approved security policies and procedures
- System configuration exports
- Asset inventories
- Access review records
- Vulnerability tracking records
- Training completion reports
- Incident response exercise results
- Backup restoration test records

Each assessment conclusion must reference its supporting evidence or state why evidence is insufficient.

## 6. Gap Documentation

Each identified gap will include:

- NIST CSF outcome ID
- Current practice and supporting evidence
- Desired target practice
- Description of the gap
- Potential business impact
- Recommended corrective action
- Responsible business owner
- Priority

## 7. Prioritization

Recommendations will be prioritized using three qualitative levels:

**High:** Significant potential business impact or urgent weakness affecting critical systems or sensitive information.

**Medium:** Meaningful security weakness requiring planned corrective action.

**Low:** Lower-impact improvement that can be addressed through routine security maintenance.

The assessment will consider implementation effort and the company's limited IT resources when developing the remediation roadmap.

These levels are project-defined judgments and are not NIST CSF implementation tiers.

## 8. Deliverables

The assessment will produce:

- Current and Target CSF Profiles
- Evidence request register
- Security gap assessment
- Recommended corrective actions
- Prioritized 90-day improvement roadmap
- Executive risk summary
